# EchoFarm：类玩家 AI 化身设计

## 1. 产品定义

EchoFarm 为《星露谷物语》增加一个能够通过观察玩家来学习的 AI 化身。

玩家不需要和它聊天，也不需要编写脚本。玩家只需正常游玩并开启一次“教学”，EchoFarm 就会记录这段经历，逐步形成玩家画像，把低层操作理解成可复用的游戏技能。之后，一个具有相同习惯和决策风格的“回声化身”会出现在游戏世界中，与玩家同时活动，并在变化后的环境里自主完成学到的目标。

核心体验是：**玩家通过游玩来训练另一个自己。**

## 2. AI 为什么不可替代

EchoFarm 不保存坐标宏，也不按时间轴机械重放。AI 拥有四项核心职责：

1. **行为理解**：从移动、切换工具、浇水、收获、开箱等连续事件中划分行为片段；
2. **意图推断**：判断玩家是在“照料全部作物”，而不是“依次点击这些坐标”；
3. **技能编译**：把一次示范转换成包含目标、前置条件、停止条件和失败策略的技能程序；
4. **实时重规划**：当雨天、布局变化、工具资源不足或目标消失时，修改剩余计划。

没有模型时，《星露谷物语》本身继续正常运行，但 Echo 无法学习新技能或处理新情况。规则代码只负责安全地执行 AI 决策，不伪装成智能。

项目不使用 RAG。模型上下文只包含当前世界状态、玩家示范轨迹、已有玩家画像、可执行动作目录和结构化输出约束。

## 3. 玩家画像

EchoFarm 持续维护一份有证据来源的 `PlayerModel`，而不是自由文本人物小传。MVP 画像包含：

- 常见晨间任务及顺序；
- 偏好的农场路线和箱子；
- 体力保留倾向；
- 面对未成熟作物、缺水和背包已满时的处理习惯；
- 重视效率还是保持原有顺序；
- 每项习惯的观察次数与置信度。

第一次示范生成临时画像；后续示范只在新证据足够时更新对应习惯，避免一次偶然操作永久改变 Echo。

画像的作用不是展示标签，而是影响 Echo 的实际行为。例如，谨慎型玩家会保留体力并提前停止，效率型玩家会重排路线，习惯固定箱子的玩家会优先寻找该箱子。

## 4. MVP 游戏体验

### 4.1 教学

1. 玩家在游戏内启用“记录回声”；
2. 玩家正常完成一次农场晨间流程；
3. C# Bridge 记录动作及动作前后的世界状态；
4. Go/Eino 将轨迹编译为 `MorningFarmRoutine`；
5. 游戏内出现一页简短的“回声记忆”，显示 Echo 学到了什么。

### 4.2 AI 化身进入游戏

1. 第二天玩家召唤一个半透明的玩家化身；
2. Echo 与玩家同时存在，不接管玩家角色；
3. Echo 根据当前农场重新确定需要处理的目标；
4. Go 生成高层动作，C# Bridge 在游戏主线程执行；
5. 每次动作结果返回 Go，必要时由 Eino 触发重规划；
6. 当目标完成或安全条件不满足时，Echo 自主结束当天工作。

### 4.3 演示中的环境变化

固定 Demo 至少展示三种泛化：

- 第二天下雨，Echo 判断无需浇水；
- 增加或移动作物，Echo 根据状态寻找新目标；
- 水壶缺水，Echo 中断原计划，先补水再继续。

这些变化不能通过重放昨日坐标正确完成，用来直接证明 Echo 学到的是目标而不是按键序列。

## 5. MVP 能力边界

第一阶段只学习一类技能：农场晨间照料。

支持的高层动作：

- 寻找需要浇水的作物；
- 寻找已成熟作物；
- 移动到可交互位置；
- 选择并使用水壶；
- 前往水源补水；
- 收获作物；
- 将收获物放入玩家示范过的箱子；
- 在体力、时间或异常条件下停止。

第一阶段不学习钓鱼、战斗、下矿、社交和购买行为，也不让 Echo 自由操作未知物品。先把一个技能做到真正可学习、可泛化、可在游戏中稳定执行。

## 6. 技术架构

### 6.1 Go + Eino：唯一 AI 大脑

新增 `echofarm-core/`，承担全部智能逻辑：

- `Recorder Ingestor`：接收并压缩游戏事件；
- `Player Modeler`：基于新证据更新结构化玩家画像；
- `Skill Compiler`：把示范编译成可执行技能；
- `Echo Policy`：依据技能、画像和实时世界状态选择下一高层动作；
- `Replanner`：消费动作失败原因，重写剩余步骤；
- `Memory Store`：使用 SQLite 保存画像、技能和执行会话。

Eino 编排两条图：

```text
示范轨迹 -> 行为分段 -> 意图推断 -> 技能编译 -> 画像更新

世界状态 -> 读取画像与技能 -> 选择动作 -> 执行反馈
                                  ^          |
                                  |--重规划--|
```

模型只输出受约束的 `PlayerModelPatch`、`SkillProgram` 和 `HighLevelAction`，不直接生成游戏内存修改或任意代码。

### 6.2 C# / SMAPI：薄游戏桥

《星露谷物语》的标准 Mod 接口是 SMAPI/.NET，因此保留 `stardew-echo-mod/`：

- 监听玩家输入、工具使用、作物变化、天气、时间和位置；
- 生成与游戏内部类型解耦的世界快照；
- 绘制和移动 Echo 化身；
- 将高层动作转换成受控的 SMAPI 操作；
- 拒绝越权、过期或当前状态不可执行的动作；
- 确保所有游戏状态修改都发生在游戏主线程。

C# 不包含模型调用、画像推断或计划逻辑，只是传感器与执行器。

### 6.3 本地通信

- C# 与 Go 默认通过本机 HTTP 通信；
- 教学轨迹按批次上传，执行阶段按高层动作交互；
- 每次会话使用 `saveId + sessionId` 隔离；
- Go 默认只监听 `127.0.0.1`；
- 网络或模型不可用时 Echo 停止，基础游戏不受影响。

## 7. 核心数据契约

### 7.1 WorldSnapshot

包含游戏日期、天气、时间、玩家位置、体力、背包摘要、工具状态、可见作物、水源、箱子和障碍物。只传递当前决策需要的结构化状态。

### 7.2 DemonstrationEvent

包含动作类型、动作对象、动作前后状态差异、位置、时间和结果。连续移动事件在 C# 侧合并，避免把无意义的帧数据交给模型。

### 7.3 SkillProgram

```text
name
goal
preconditions
target_selector
preferred_order
steps
success_conditions
stop_conditions
recovery_strategies
```

### 7.4 HighLevelAction

只允许动作目录中声明的操作，例如 `move_to`、`equip_tool`、`water_target`、`refill_can`、`harvest_target`、`deposit_items` 和 `stop_session`。

## 8. AI 执行策略

AI 不参与逐帧移动。每次模型决策产生一个高层动作，Go 将其拆成确定性执行步骤，C# 负责寻路和游戏操作。这样既保证 AI 决定“做什么和为什么”，又避免网络延迟直接破坏游戏手感。

需要重新调用模型的情况：

- 当前技能首次部署到新环境；
- 高层动作的前置条件已变化；
- 确定性执行返回可恢复失败；
- 技能完成后需要更新玩家画像；
- 连续观察证明旧画像已经过时。

普通路径移动、动画等待和已知动作重试不调用模型。

## 9. 安全与游戏完整性

- 不直接读写存档文件；
- 不允许模型设置金币、好感度或生成任意物品；
- 每个动作执行前由 C# 使用最新世界状态重新检查；
- Echo 使用独立状态，不消耗或覆盖玩家当前控制；
- 保存前停止未完成动作并持久化会话；
- 切换存档后不复用其他玩家画像；
- Go 或模型故障只禁用 Echo，不影响游戏加载、保存和退出。

## 10. 工程结构

```text
Stardew-Sage/
├── echofarm-core/              # Go + Eino AI 大脑
│   ├── cmd/echofarm/
│   ├── internal/modeler/
│   ├── internal/compiler/
│   ├── internal/policy/
│   ├── internal/replanner/
│   └── internal/memory/
├── stardew-echo-mod/           # C# / SMAPI 游戏桥
├── contracts/                  # JSON Schema 与动作目录
├── demo/                       # 固定存档说明和演示轨迹
└── docs/
```

现有 Java、Vue 和管理后台代码不进入新主链路。第一阶段在当前分支新增干净实现；确认新闭环可运行后，再决定删除还是迁移旧目录，避免一开始做无关重构。

## 11. 开发顺序

1. 定义世界快照、示范事件、玩家画像、技能程序和动作契约；
2. 用 Go 建立本地服务、SQLite 和 Eino 基础图；
3. 先用录制好的示范事件完成“轨迹 -> 技能 -> 下一动作”；
4. 创建 C# SMAPI Bridge，采集真实农场行为；
5. 在游戏中绘制 Echo 并执行浇水动作；
6. 加入雨天跳过、寻找新作物和水壶补水；
7. 将执行结果反馈给 Eino，完成失败重规划和画像更新；
8. 准备一个稳定的游戏内演示场景。

## 12. 开发质量保障

测试不作为产品卖点，但必须保护游戏存档和 AI 边界：

- Go 对契约解析、画像合并、技能状态迁移和动作白名单做单元测试；
- Eino 模型节点使用 Stub 覆盖成功、非法输出和超时；
- C# 对事件合并、快照映射和动作前置检查做测试；
- 使用一个不包含个人数据的测试存档完成游戏内冒烟验证；
- 所有测试配置使用环境变量，仓库不保存有效密钥。

## 13. MVP 完成标准

- 玩家能在真实游戏中完成一次教学录制；
- Eino 能从轨迹生成结构化玩家画像和 `MorningFarmRoutine`；
- Echo 作为独立化身与玩家同时出现在农场；
- Echo 能在新一天自主选择并执行浇水、补水和收获动作；
- 雨天或作物布局改变时不会机械重放旧坐标；
- 一次可恢复失败能够触发重规划并继续执行；
- 模型或 Go 不可用时基础游戏仍能正常保存和退出；
- 主链路不依赖 Java、RAG、远程数据库或 Web 聊天页面。

## 14. 演示脚本

1. 玩家开启教学，亲自完成一次晨间农活；
2. 游戏内“回声记忆”显示 AI 推断出的目标和行为偏好；
3. 进入下一天，改变作物布局并设置雨天；
4. 召唤 Echo，玩家离开农场做其他事情；
5. Echo 跳过无效浇水，发现新成熟作物并自主处理；
6. 制造水壶缺水，展示 Echo 中断、补水和继续工作；
7. 玩家回到农场，看到 Echo 与自己并行参与世界后的实际结果。
